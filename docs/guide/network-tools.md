# 网络诊断与测速

打开「网络工具」，按分类点击小图标卡片，在独立窗口中操作。

![网络工具按地址、连通性、发现和中转分类的入口](/images/network-tools.png)

先按任务选择卡片，再填写目标。例如排查域名点「DNS / DoH」，排查链路点「Ping / 路由追踪」，测吞吐点「iperf3」。

## 按问题选择工具

| 要排查的问题 | 工具与操作 |
| --- | --- |
| 地址是否属于同一网段 | 「CIDR 计算」输入地址和前缀，查看网络范围 |
| 域名解析结果不符 | 「DNS / DoH」选择记录类型、服务器和 UDP / TCP / DoH 后查询 |
| TLS 证书或算法问题 | 「证书与密码」检查直接 TLS 连接、证书或密码算法 |
| 主机是否可达、经过哪些路由 | 「Ping / 路由追踪」选择对应模式并开始 |
| 端口是否开放 | 「端口扫描」填写目标和端口范围，结果只列开放项 |
| 查找可信局域网内设备 | 「内网扫描」选择探测范围 |
| 判断 NAT 与网关能力 | 「NAT 类型」查看多项观测证据；「UPnP 发现」检查网关响应 |
| 检查本机配置或 Hosts | 「本地信息」「Hosts 管理器」 |

DNS / DoH 直接使用协议，不依赖 `nslookup`；DoH 正常验证 TLS 证书。TLS 检查当前只处理直接 TLS，不支持 STARTTLS。端口扫描一次最多 1,024 个端口。Hosts 匹配完整域名，应用前备份并检测并发修改。

NAT 结果受网络与服务响应影响，不能仅根据一次失败判定类型。协议与算法细节见[证书与密码说明](../security-crypto.md)。

## iperf3 本机示例

1. 打开「iperf3」，模式选服务端，端口 `5201`。本机验证监听 `127.0.0.1`；跨机时监听实际网卡地址或 `0.0.0.0`，然后开始监听。
2. 使用另一个支持标准 iperf3 的客户端，连接同一地址和端口。也可在另一台 EmbedDesk 中选择客户端，填写服务端实际地址。
3. 客户端选择 TCP 或 UDP、上传或下载，先用较短时长和适当限速运行，再查看速率及相应统计。
4. 测试结束后停止不再需要的监听。

下载使用反向模式 `-R`。UDP 同时需要 TCP 控制连接，跨机使用时需允许相同端口的 TCP 与 UDP；TCP 写入块大小不等于线上单包大小。

当前范围为单流、按时长、`-P 1`、`-O 0`，时长 1–3,600 秒；没有多流、双向同时、SCTP、认证或 CPU / 重传统计。UDP 可显示包率、丢包、乱序和抖动。

选择公共测速节点后，点击开始才产生测试流量。公开节点的历史验证不保证当前可用；客户端和内置服务端的验证范围不同，见[协议与历史实测](../third-party/iperf3-protocol.md)。

# 常见问题

## 双击 EXE 提示缺少 .NET

默认精简包需要 **.NET 8 Desktop Runtime x64**，仅有 ASP.NET Runtime 或其他架构运行时可能不够。安装入口见[快速开始](getting-started.md#准备运行环境)。终端另外需要 WebView2 Runtime。

## 调试助手为什么没有默认串口标签

这是正常空状态。点击「开始第一个调试会话」或 `+`，在内部弹窗中选择类型。串口、网络、PID 和摄像头都在同一排标签中。

## PID 里的 UDP 如何选择客户端或服务端

新建或停止后编辑连接，选择「TCP/UDP 客户端」或「TCP/UDP 服务端」，再将协议设为 UDP。客户端填写远程地址，服务端填写本机监听地址。工具 UDP 服务端自动锁定首个发送端，断开重连后可换设备。

## 无法修改连接设置

先停止连接和发送任务，再打开当前标签的连接设置。应用修改不会自动重连，也不会修改其他标签。

## TCP 连接被拒绝或监听失败

确认服务端已启动，客户端目标与服务端协议、端口一致。监听地址必须是本机地址；`127.0.0.1` 不接受其他电脑的连接。端口占用时换端口或结束占用方自己的监听，跨机还需检查防火墙。

## UDP 显示启动却没有数据

UDP 没有 TCP 式握手，启动不代表对方在线。核对对端地址和源端口、监听地址、防火墙及首个发送端锁定。PID / 摄像头还需核对协议格式。

## 串口打开失败或显示被共享占用

先断开本地调试、烧录或远程使用。共享串口需要取消共享后才能在本应用本地打开；其他程序也可能占用物理 COM。设备拔插后重新确认当前编号和描述。

## 有 RX，但 PID 没曲线或摄像头没图像

连接只提供传输，固件必须发送兼容的帧。检查地址、命令、长度、字节序及校验；JPEG 连续流和兼容分帧协议也不能混用。详见[设备调试指南](pid-camera.md)。

## 连接中心为什么没有设备 ID

当前没有内置公共中继。先在设置中配置双方可访问的同一中继，检查准入、TLS 和代理错误；保存后的连接选项下次上线生效。本地串口与本机网络调试不依赖连接中心。

## 远程串口一定需要安装驱动吗

应用内使用不需要。让其他软件看到系统 COM 才涉及单独安装 com0com，属于实验性能力，见[系统虚拟串口](../VirtualSerialPorts.md)。

## 关闭窗口后为什么仍在通信

收起到托盘会保留连接和后台任务。需要结束时断开会话，或从托盘真正退出。PID 板端控制不会因为上位机关闭而自动停止。

## 接收历史变少了，累计字节却没减少

历史有 1,000 条 / 4 MiB 上限，裁剪只移除旧显示记录，不减少累计 RX/TX。需要完整原始记录时提前录制；接收窗口不是无限抓包存档。

## 局域网文件发现不到，或退出后任务不见了

跨广播域或防火墙可能阻止发现，可手填当前 TCP HTTP 地址和访问码。任务列表不跨进程保存，但断点文件保留；重新发起同版本文件传输时可续传，见[文件传输指南](lan-files.md)。

## 如何报告问题

在 [GitHub Issues](https://github.com/Daofengql/EmbedDesk/issues) 提供版本、预期结果、实际结果、复现步骤及脱敏后的截图。不要附真实密码、密钥、令牌、完整连接配置或业务录制；用回环地址与模拟载荷尽量复现。

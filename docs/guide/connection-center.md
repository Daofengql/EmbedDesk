# 连接中心与共享

连接中心用于让另一台 EmbedDesk 访问本机发布的串口或 TCP/UDP 服务。两端使用设备 ID 授权连接，程序自动尝试局域网直连，失败后回退到中继。

## 准备中继与授权

1. 可直接使用软件内置的「免费中继 1」，或准备[自部署中继](https://daofengql.github.io/EmbedDesk.Relay/deployment/)。新安装默认选择内置节点，升级保留已有默认选择。
2. 在右上角设置 →「中继服务器」添加地址及该节点的准入 Token，或从剪贴板导入连接代码，核对后添加 / 更新并选择默认节点。保存后下次上线生效。
3. 应用启动后自动上线，在连接中心查看设备 ID 和连接密码。
4. 连接方填写对方 ID 与密码。密码留空会请求对方人工授权，等待期间可以取消。

两端应使用同一中继。即使准备使用局域网直连，设备 ID 查询和初始授权仍依赖中继。内置免费节点使用 HTTPS / WSS，由反向代理提供 TLS，设备数据正文另按既有协议加密。人工授权依赖可信中继与链路。

节点的网页控制台位于 `/console/`，所有登录账号在“中继接入”看到相同的公共连接代码。准入 Token 只作简单扫描过滤，由节点管理员维护，更新仅影响后续设备注册。它不授予访问其他设备的权限。

设备初次接入为匿名设备，每台使用节点默认带宽。注册用户登录控制台后，在“设备管理 → 绑定设备”输入自己的设备 ID，绑定尚未归属账号的设备；管理员也可分配归属。知道未绑定设备 ID 即可领取，绑定流程不证明真实设备持有。绑定后同账号全部设备共享总带宽；绑定、转移或修改单用户配额会断开关联设备，再由客户端重连应用。访客账号只读查看分配给它的设备。

## 共享串口

在被连接方的「映射设置」中点击「添加串口」，选择设备并发布。连接方授权后，在串口映射列点击添加，从弹窗中选择对端已发布的 COM，再选择在本软件内使用或本机虚拟 COM 对。应用内使用会进入串口调试，填写参数并连接；对方 COM 也会出现在串口调试的选择列表中。

启用共享只做应用内软件预留，不会提前打开设备或改变 DTR/RTS。连接方实际打开时才提交串口参数，被连接方成功打开后才算连接成功。远端关闭后释放硬件，共享预留保留；本地要重新调试或烧录，需要取消共享。

应用内远程串口无需驱动。如果必须让其他软件看到系统 COM，另看[系统虚拟串口（实验性）](../VirtualSerialPorts.md)。

## 发布网络服务

在被连接方点击「添加服务」，选择 TCP 或 UDP，填写目标主机和端口。目标可以是被连接方本机，也可以是它能访问的网络设备。

连接方建立设备会话后，在「映射设置」的端口映射列点击添加。弹窗中先选择对端已发布的 TCP/UDP 目标，核对其主机和端口，再填写本机映射端口；监听地址固定为 `127.0.0.1`，不能选择其他范围，协议由所选目标决定。核对两端预览后保存并启用，端口无效、占用或对端离线时留在弹窗显示错误。映射方向始终如下：

```text
连接方 127.0.0.1:LOCAL_PORT
    → 对端已发布的 TCP/UDP 服务
    → 被连接方可访问的 HOST:PORT
```

之后在本地工具中访问这个回环端口。监听启用只代表本机端口已准备，首次实际访问才打开对端目标通道；失败时查看映射状态和真实错误。

映射不是任意网段 VPN，也没有反向映射选择。授权设备会话可以访问对端当前发布的全部服务，应只发布本次需要的目标。

## 掉线与退出

重连只恢复节点上线，不恢复设备授权、实际串口或活动映射监听，需要重新连接和启用。收起到托盘会保留连接和共享预留；真正退出才清理任务。

UDP 映射通过认证 TCP 直连或加密 WebSocket 转发，不是 UDP 打洞。容量、限速和认证细节见[设备连接与安全边界](../DeviceConnections.md)。

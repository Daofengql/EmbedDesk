# 局域网文件传输

在「网络工具」打开「局域网文件」。它有独立服务端和客户端，不需要连接中心或中继，用于可信 IPv4 局域网。

## 服务端：选择共享目录

1. 在「服务端」选择共享根目录并启动服务。
2. 点击「复制连接信息」，通过你信任的渠道交给对方；也可以分别提供地址和访问码。
3. 保持窗口或应用在后台运行，按需要观察传输任务。

![局域网文件服务端选择共享根目录并启动服务](/images/lan-server.png)

先点右侧「选择」指定目录，再点「启动服务」。图中尚未启动，所以还没有地址、访问码，也不能复制连接信息。

连接信息包含本次访问码，Base64 只是编码。发现广播不包含访问码，重启服务后应重新获取连接信息。只共享实际需要的目录。

## 客户端：连接与传输

1. 切到「客户端」，点击「从剪贴板导入」，或主动发现服务后填写访问码；发现失败时手动填入地址。
2. 连接后浏览共享根目录及其子目录，使用 `..` 返回上级。
3. 上传时可从任意本地目录选择源文件，远端目标必须是共享根目录内的相对路径；下载时选择本地保存位置。
4. 遇到覆盖提示先核对目标。右下角悬浮传输队列显示进度、速率和剩余时间，可暂停或继续。

![局域网文件客户端的发现、剪贴板导入和连接入口](/images/lan-client.png)

收到对方连接信息后先「从剪贴板导入」，核对地址和访问码，再点「连接」。连接成功后，下方列表显示共享根目录的内容。

上传同时处理最多 3 个文件，每个文件默认 3 路分块。程序使用持久化断点，成功完成后才原子替换目标；短暂断线会有限重试。没有固定单文件大小上限，仍受磁盘空间和目标文件系统限制，例如 FAT32 的单文件限制。

## 后台与断点

关闭窗口时可选择后台保留；重开会恢复同一实例。真正退出会取消并等待清理。任务列表不跨进程保存，但断点文件保留，再次对同一版本发起传输时可续传。

逐块 SHA-256 用于本次传输校验；版本识别只采样首尾，不是整文件摘要，也不重新扫描所有已提交旧块。不要把它当作旧缓存静默损坏检测。

## 连接失败时

检查双方是否在可互访的 IPv4 局域网、防火墙是否允许服务端实际 TCP 端口及 UDP `39127` 发现。跨广播域通常不能自动发现，可尝试手填服务端地址。访问码不匹配时重新复制当前服务的连接信息。

文件正文使用 TCP HTTP，UDP 只负责发现。内容与访问码均不加密；不通过公网中继、代理或重定向，也不建立系统目录映射。完整协议和路径边界见[局域网文件技术说明](../LanFiles.md)。

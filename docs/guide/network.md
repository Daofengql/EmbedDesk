# TCP / UDP 与 MQTT

原始网络会话用于查看和发送字节。新建时先选客户端或服务端，再在表单中选择 TCP / UDP。

## 选择角色与协议

| 方式 | 填写的地址 | 行为 |
| --- | --- | --- |
| TCP 客户端 | 对方的远程地址与端口 | 主动连接，可设置本地绑定、超时及自动重连 |
| TCP 服务端 | 本机监听地址与端口 | 等待客户端，可维护多个对端 |
| UDP 客户端 | 指定远程地址与端口 | 只与指定目标通信 |
| UDP 服务端 | 本机监听地址与端口 | 接收多个发送方，可锁定首个发送端 |

客户端的远程地址必须指向对方；服务端的监听地址必须属于本机。`127.0.0.1` 只允许本机访问，`0.0.0.0` 监听所有 IPv4 网卡。对外监听后还需按实际范围配置 Windows 防火墙。

首次使用可按[快速开始](getting-started.md#发送第一条报文)在本机验证两端。跨机连接前，先确认双方协议、端口和网络可达性一致。

![TCP/UDP 服务端表单，选择协议后填写本机监听地址](/images/tcp-server.png)

图中监听 `0.0.0.0:9000`，表示所有本机 IPv4 网卡。仅做本机示例时改为 `127.0.0.1`；需要 UDP 时在「协议」中切换。

## 收发与对端选择

创建原始网络会话时点击「创建并启动」。在底部选择文本或 HEX 发送，在接收区查看结果。TCP 是字节流，一次发送可能对应多次读取，多次发送也可能合并；不要把一行接收记录直接当作应用协议的一帧。UDP 默认按数据报分行。

服务端发送前可选择全部对端或指定对端。UDP 服务端只有收到报文后才知道发送方；锁定首个发送端可以避免混入其他来源，重新连接后解除锁定。

PID 与摄像头的网络连接使用相同的角色名称，但附带自己的协议解析，并自动限制单个工具会话的设备来源。步骤见[设备调试](pid-camera.md)。

## MQTT 发布与订阅

在新建弹窗的「应用协议」选择「MQTT 客户端」，填写 Broker 地址、端口、主题，以及服务端要求的用户名和密码。需要 TLS 时启用对应选项，并使用服务端实际支持的端口。

连接成功后按主题订阅和发布。收不到消息时，检查订阅主题、发布主题、Broker 的访问控制和 TLS 连接错误。不要将账号或含业务数据的载荷放入问题报告。

## 修改与停止

断开连接并停止发送任务后再编辑连接参数。修改只影响当前标签；停止服务端会结束该会话的监听和对端连接。

HTTP 新建入口暂缓，当前没有可直接使用的专用 HTTP 调试器。

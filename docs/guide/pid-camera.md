# PID 与摄像头

这两种会话会解析特定设备协议。先确认固件符合[公共帧与校验](../reference/debug-protocol.md)，仅建立 TCP 或串口连接不代表协议已互通。[PID 协议](../reference/pid-protocol.md)和[摄像头协议](../reference/camera-protocol.md)提供字段、命令与完整 HEX 示例。

## 连接方式

在「调试助手」点击 `+`，选择「PID 调试」或「摄像头调试」，再选择连接方式。

| 连接方式 | 关键设置 |
| --- | --- |
| 串口 | 设备、波特率和串口格式；可先建标签再选择设备 |
| TCP/UDP 客户端 | 选择协议，填写远程地址与端口 |
| TCP/UDP 服务端 | 选择协议，填写本机监听地址与端口 |

创建后在标签内点击连接。工具 TCP 服务端只接受一个设备会话；UDP 服务端自动锁定本次连接的首个发送端，重新连接后解除锁定。一个工具标签只解析一个设备来源，多个控制器应分别创建标签。

![PID 新建连接选择 TCP/UDP 服务端，并将协议设为 TCP](/images/pid-server.png)

图中是本机回环演示端口。实际联调时，开发板作为客户端连接这里填写的监听地址和端口；若开发板提供服务端，则应反过来选择「TCP/UDP 客户端」。

## PID 参数与曲线

1. 选择 CH1–CH5 中的通道，确认实际值与设备状态开始更新。
2. 填写 P / I / D 并发送；按固件范围设置目标值和周期。周期单位由固件定义。
3. 根据固件需要发送启动、停止或复位指令；运行状态以设备返回的数据包为准。
4. 选择时间窗、显示通道和目标值；滚轮缩放时间轴，鼠标读数可查看时间与数值。

![测试环境中的 PID 工作区，尚未连接设备](/images/pid-workspace.png)

每通道保留最近 2,000 个实际值，时间窗为 50 ms–600 s，时间来自主机接收时刻。暂停显示时仍会接收数据。移动平均和指数平滑只改变显示及可选导出列，原始采样不变，平滑会带来滞后。

导出 CSV 时保存当前保留历史；启用附加滤波列后，`actual` 仍为原始值，`filtered_actual` 为显示滤波结果。

**关闭会话不会自动停止板端控制。** 如需停止设备，应先发停止指令并核对返回状态，再断开连接。

## 摄像头图像

连接前选择兼容分帧协议或 JPEG 连续流。分帧协议支持 JPEG、BMP、PNG、RGB565、RGB888；RGB565 应核对 LE / BE 字节序。JPEG 连续流不添加协议头，也没有寄存器操作。

![摄像头标签中的接收格式、CRC、RGB565 字节序和寄存器设置](/images/camera-workspace.png)

上方选择接收格式与显示设备，下方设置寄存器地址和值的宽度。图中尚未连接；收到有效格式包和图像包后，预览区才显示画面。报文示例见[摄像头协议](../reference/camera-protocol.md)。

默认启用 CRC-16 校验。关闭校验仍要求分帧数据包含尾部校验字段，不能据此直接接收任意原始像素流。图像限制为 8 MiB、4096×4096 且不超过 4,194,304 像素。

分帧协议可显示两个设备地址，并按设置的 1–4 字节宽度读写寄存器。核对寄存器地址、值宽度和固件协议后再发送。保存图片前确认显示的是预期设备的最新帧。

## 无曲线或无图像时

先看 RX 是否增长，再检查角色、TCP/UDP、帧头、长度、地址、命令和校验。协议中出现的整型与浮点字节序必须和固件一致。单纯把任意数字文本或摄像头视频流发到端口，不能生成兼容数据。

协议说明中的校验解释尚未完成真实开发板互通确认；本机回环与模拟数据检查不能替代摄像头或 PID 控制器实测。

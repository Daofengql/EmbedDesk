# 数据与调试辅助

主导航中的串口、网络、PID 和摄像头调试已合并为「调试助手」。四类会话共用一排一级标签，不嵌套功能标签或会话列表。默认无标签，显示「开始第一个调试会话」；`+` 与空状态按钮均在主界面内打开分类新建弹窗。基础通信为串口调试、TCP/UDP 客户端和 TCP/UDP 服务端，进入网络表单后再选择协议；应用协议暂时仅保留 MQTT，HTTP 新建入口待设计确定后再规划。连接参数在弹窗中设置，不提供连接预设栏。PID 与摄像头直接显示在标签内容区，切换时继续接收与累计，仅暂停隐藏视图的绘制。二进制编辑器继续位于「嵌入式工具」原有入口。连接设置和生命周期详见 [调试助手合并设计](DebugAssistantDesign.md)。

## 摄像头调试助手

支持串口、TCP 客户端 / 服务端和 UDP，接收兼容的分帧图像传输或不带包头的 JPEG 连续流。分帧图像支持 JPEG、BMP、PNG、RGB565 和 RGB888，可显示两个设备并进行有限宽度的寄存器读写。默认校验 CRC-16；关闭校验时仍要求保留帧尾校验字段。图像帧限制为 8 MiB、4096×4096 和 4,194,304 像素以内。

## PID 调试助手

每个通道保留最近 2,000 个实际值，累计采样数不随裁剪减少。目标值、参数和运行状态独立同步。曲线可选择 50 ms 到 600 s 的时间窗，也可以滚轮缩放；网格分为 10×10，短时间窗显示到毫秒级。采样点开关和鼠标读数可以查看时间、目标、原始值及显示值。时间为主机接收时间，并非开发板提供的硬件时间戳。

显示滤波提供关闭、移动平均（窗口 N 为 1–1,000）和指数平滑（0 < α ≤ 1），默认关闭。各通道分别从保留历史的第一点计算；移动平均使用尾随窗口，点数不足时取已有点的均值；指数平滑以第一点为初值，按 `y += α × (x − y)` 计算。结果保留小数，目标值不滤波。这不会增加设备采样精度，也不改变板端控制算法；平滑会产生滞后。

滤波只改变绘图和可选的 `filtered_actual` 导出列，`actual` 始终是设备原始采样。CSV 导出捕获所有通道的保留历史与当前滤波设置，后台写完后替换目标；支持取消，退出会等待清理。暂停显示仍继续接收数据。启动 / 停止指令发送完成仅表示本地发送完成，收到设备状态包后才同步运行状态；关闭窗口不自动停止板端控制。

## 二进制编辑器

采用连续 HEX / ASCII 视图，按可见行读取文件，支持定位、HEX / UTF-8 跨块搜索、键盘覆盖编辑、撤销 / 重做和原子保存。编辑期间原文件不被改写，保存完成后才替换目标文件；取消保存会清理临时文件。当前不支持插入 / 删除字节，最多保留 65,536 个修改字节和 128 次撤销操作；`.hex` 文件按原始字节处理，不解析 Intel HEX 记录。

## 传输和兼容实现

固件对接的逐字段说明、校验算法与完整报文见[公共帧](reference/debug-protocol.md)、[PID 协议](reference/pid-protocol.md)和[摄像头协议](reference/camera-protocol.md)。本页保留工具功能与实现边界。

PID / 摄像头连接实现位于 `DebugToolConnection`。连接方式统一为「串口」「TCP/UDP 客户端」「TCP/UDP 服务端」，选择网络角色后再选择 TCP 或 UDP；新建、编辑和兼容工具窗口均使用相同分类。公共编辑器可设置串口设备、波特率、数据位、校验、停止位和流控，默认 8N1、无流控，不主动置 DTR / RTS；复用统一串口资源服务，并支持应用内远程串口。TCP 客户端支持本地绑定和 100–120,000 ms 超时（默认 10 秒），服务端每次接受一个开发板，断开后需重新连接。UDP 客户端只与指定远程地址收发；UDP 服务端监听本机端口，自动锁定本次会话第一个发送端，重新连接后解除锁定。原始 UDP 多对端监听仅供网络标签使用，避免不同设备的协议数据混入同一个解析器。工具串口接收最多排队 32 包、单包最多 256 KiB，处理跟不上时明确停止；TCP / UDP 顺序处理，不为每帧派生任务。关闭等待连接、发送、寄存器应答或导出任务清理。

协议解析见 `DebugToolProtocol.cs`，依据公开[图像传输文档](https://www.firebbs.cn/forum.php?mod=viewthread&tid=29788)（2020-06-08，v0.0.1）与 [PID 通信文档](https://www.firebbs.cn/forum.php?mod=viewthread&tid=29923)（2020-06-30，v0.0.1）独立实现；[工具文档入口](https://doc.embedfire.com/products/link/zh/latest/deskapp/ebf_trace_tool.html)用于交叉核对。没有移植第三方工具源码、界面素材或二进制依赖，产品界面仅使用通用功能名称。

通用包头为 `53 5A 48 59`、设备地址 1 字节、整包长度 UInt32 LE、命令 1 字节。图像包尾为 CRC-16 两字节 LE，采用初值 FFFF、反射多项式 A001、异或输出 0000（`123456789 → 4B37`）；PID 包尾为前面所有字节累加的低八位。公开图像文档的多项式 / 字节序描述存在歧义，当前选取上述明确解释并提供 RGB565 LE / BE 开关，尚无实机互通确认。

| 格式 | 接收 / 发送定义 |
| --- | --- |
| 图像设备 | 地址 0 / 1；命令 01 为类型 1 字节、宽 UInt16 LE、高 UInt16 LE；02 为图像；00 为确认码（00 成功、01 失败） |
| 图像类型 | 01 JPEG、02 BMP、03 PNG、04 RGB565、05 RGB888（RGB 通道顺序）；公开文档中未明确布局的二值格式暂不实现 |
| 寄存器 | 10 为写入（地址 + 值），11 为读取（序号 UInt16 LE + 地址）；读取响应为确认码 + 序号 + 值。地址和值宽度分别选择 1–4 字节，均低字节在前 |
| PID 通道 | 地址 1–5；接收 01 目标 Int32、02 实际 Int32、03 三个 float32 的 P / I / D、04 运行、05 停止、06 周期 UInt32，数值均 LE |
| PID 下发 | 10 参数、11 目标、12 启动、13 停止、14 复位、15 周期；周期单位由固件定义。无参数包为 11 字节 |

图像 CRC 不匹配时，启用校验的接收端不进行解码，对格式 / 图像包回复失败确认。JPEG 连续流通过 JPEG 段长度、元数据和熵编码转义解析边界，不向流添加协议头，也不提供寄存器操作。解码图像采用 Windows WPF 内置能力。

这些工具的自动化回环检查覆盖帧解析、传输生命周期、文件保存、滤波计算和窗口布局；回环检查不能替代真实开发板、摄像头或 PID 控制器实测。

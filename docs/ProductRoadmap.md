# EmbedDesk 产品方向记录（讨论稿）

本文记录讨论中的产品方向，便于后续拆解和评估，不代表已实现、已排期或对在线服务可用性作出承诺。

## 当前基础

- EmbedDesk 已有 SSH、RDP、VNC、网络串口桥接、TCP / UDP / MQTT、DNS / DoH、TLS 检查、Ping / 路由追踪、端口扫描、内网发现、STUN NAT / UPnP 和 iperf3 等功能。
- 网络调试服务端当前显示监听地址；当绑定 `0.0.0.0` 时，还可进一步列出本机网卡地址，帮助对端用户选择连接目标。
- 网络功能以用户主动连接或启动为主；主窗口的 GitHub 图标通过默认浏览器打开开源仓库，当前没有应用内更新检查、更新下载、自动安装、云账号、配置云同步或遥测。
- 远程连接配置、SSH 密钥路径索引和版本化应用偏好保存在 `%LOCALAPPDATA%\EmbedDesk`。远程密码不会写入配置文件。应用偏好保存窗口位置 / 尺寸、上次主工作区、远程和网络会话栏状态、本地串口通信参数、网络显示偏好，以及不含密码的网络连接预设；不会恢复活动连接，也不保存发送内容或接收历史。

## 建议的产品原则

- 本地调试、固件工具和已有连接功能在离线时继续可用；新增在线服务按需使用，并清楚显示正在连接谁、传输什么以及由谁中转。
- 不默认采集遥测、不上传串口内容或日志。联网诊断和共享会话由用户明确发起，结束后可撤销。
- 默认保存可复用的配置，不自动恢复活动连接、串口占用或公网监听，避免启动应用时意外操作设备或暴露服务。
- 任何“免费”在线能力都应公开服务端限额、带宽 / 流量限制、保留时长和可用性边界；在服务成本和滥用控制明确前不承诺永久免费或不限量。

## 建议实施顺序

### 1. 统一设置与配置持久化（本机基础能力已实现）

`%LOCALAPPDATA%\EmbedDesk\app-settings.json` 使用带 schema 版本的设置文件，并采用临时文件写入后替换。当前保存窗口尺寸与位置、最大化状态、上次主工作区、远程和网络会话栏宽度 / 折叠状态、网络接收区显示选项，以及按本地串口端口关联的波特率、数据位、校验位、停止位和流控参数。遇到未知 schema 时安全回退默认值。

可命名的 TCP / UDP / MQTT 和网络串口客户端预设也已实现，支持新建、加载、更新和删除；网络客户端可以选择自动路由或具体本机网卡作为 TCP / UDP 源地址。预设仅恢复表单，不自动连接或启动服务端。Ping / TCPing / 路由追踪、DNS、端口扫描、TLS 诊断、iperf3、CIDR、网段发现、NAT 与 UPnP 会保存最近使用的非敏感选项；不保存探测、查询或扫描结果、证书私钥、密码、密钥、报文或发送内容。二进制编解码窗口保留纯临时输入，避免把用户数据写入设置文件。

默认不保存发送内容、循环 / 队列载荷、接收历史、流量日志、私钥内容、密码或访问令牌。S3 访问密钥由用户选择仅在当前运行期保留，或单独保存到 Windows 凭据管理器；STCP 共享密钥也只保存到 Windows 凭据管理器，连接配置 JSON 只保存凭据索引，不保存密钥本身。主窗口现在提供非敏感配置导入 / 导出，包含命名远程连接、网络连接预设、网络串口预设和 STCP service / visitor 参数；配置包限制为 1 MiB、每类最多 100 项，导入前显示摘要并确认，同名项保留本机版本。导入不会带入密码、私钥路径 / 口令、S3 密钥、STCP 共享密钥、活动会话或探测结果。尚未提供跨设备配置同步。

### 2. 应用更新检查与下载（暂缓，先提供仓库入口）

主窗口右上角提供 GitHub 图标，点击后使用系统默认浏览器打开 [EmbedDesk 开源仓库](https://github.com/Daofengql/EmbedDesk)。应用内更新检测、下载窗口、客户端和加速代理逻辑已移除；用户可以从仓库页面自行查看版本和发布文件。

后续恢复更新功能时，优先考虑 GitHub Releases，并评估学校网络下的下载可达性与加速来源。正式自动更新前仍需建立受信任的发布签名或独立签名清单、密钥轮换、退出时替换和失败回滚流程。SHA-256 digest 可检测文件损坏，但不能独立证明发布者身份；自动更新不得静默安装。

### 3. 远程调试连接类型：S3 浏览器（已实现）

S3 浏览器放在「远程调试」连接管理器中，作为一种可保存的连接类型，与 SSH / RDP / VNC 一样从连接列表打开；打开后显示桶和对象工作区，不创建 Shell 或终端标签。当前支持 AWS S3 及用户指定的 HTTPS S3 兼容服务端点、区域和默认桶配置、桶和前缀浏览、上传、下载、删除、进度 / 取消和大文件分段上传。删除需确认；上传下载显示字节进度。凭据可只在本次应用运行期间保留，也可选择保存到 Windows 凭据管理器，并可从连接编辑器清除。默认拒绝远端 HTTP 端点，仅允许 HTTP 回环端点用于本机兼容服务测试。

不公开桶、不修改 ACL 或桶策略；当前不生成预签名分享链接。实现使用 AWS SDK for .NET 的 SigV4 和 TLS 校验，随包提供 Apache-2.0 许可文本。当前未覆盖匿名桶、ACL/策略管理、预签名分享和断点续传；AWS 账户和兼容端点尚未进行真实服务互通验证。

### 4. 本机信息查询与监听地址提示（已实现）

「网络工具」包含独立的「本地信息」窗口，显示各网卡状态、IPv4 / IPv6 与前缀、网关、DNS、MAC 地址，以及 CPU 型号 / 逻辑处理器数 / 使用率、内存总量与可用量、磁盘容量与剩余空间、Windows 版本 / 架构、系统运行时间和本机串口名称。信息每 2 秒刷新，仅在本机读取；不显示硬件序列号、环境变量、凭据或密钥。

Hosts 管理器已加入网络工具：方案草稿与系统文件应用分离，仅替换 `# >>> EmbedDesk Hosts` 与 `# <<< EmbedDesk Hosts` 管理区块，应用及恢复前自动备份并检测并发修改。当前只保留 Hosts 配置，不提供 DNS 代理：每条规则匹配一个完整域名，支持 IPv4 / IPv6，子域名需逐条添加。旧配置中的代理字段会移除；原有子域名匹配规则保留但停用，并提示核对具体域名后再启用，避免静默改变解析范围。程序启动时通过 EXE 清单申请管理员权限，取消 UAC 则不启动；Hosts 窗口无需再次提权。

TCP / UDP 服务端可选择某个启用网卡的具体 IP、本机 IPv4 / IPv6 环回、所有 IPv4 网卡（`0.0.0.0`）、所有 IPv6 网卡（`::`）或自定义地址。全局监听地址是明确选项，不需要当作普通输入。

服务端显示监听端口和可复制的连接端点；绑定全局地址时列出网卡候选地址，IPv6 端点使用方括号。网卡地址变化时自动刷新提示。客户端同样可选择本地源地址 / 出口接口，自动模式使用系统路由。界面说明可达性仍取决于防火墙、路由和 NAT；环回地址仅供本机使用，公网访问需要 VPN 或受控穿透服务。

信息查询保持本机只读，不自动上传。系统统计读取失败时显示不可用项和原因，不影响网络调试、串口或其他工作区。

### 5. 跨公网串口协作

协议层已加入 P-256 ECDH、配对密钥与握手 transcript 绑定的角色证明、HKDF-SHA-256 会话派生、双向独立密钥、AES-GCM 帧加密、连续序号 / nonce 校验，以及一次性配对凭据和独占租约状态模型。协议测试覆盖 transcript 篡改、错误角色 / 配对密钥、重放、跳号和密钥方向隔离。

目标体验是两端用户从 HTTPS API 获取一次性、高熵、短时有效的配对凭据；设备所有者在 EmbedDesk 中选择串口并明确同意共享，另一端输入凭据后建立远程串口会话。服务至少需要控制 API 和数据中继两部分：API 负责配对、授权、过期与撤销；中继转发串口字节流。

当前只有协议与状态模型，没有 HTTPS 配对 API、数据中继、串口 UI / 生命周期接入、断线租约清理或服务端限流。协议测试不是在线互通验证；在服务端与双方设备确认流程实现前，不能用于真实远程共享。完成版还需服务端尽量只处理路由和计量元数据、不保存串口内容，并在界面清晰显示本地串口、远端参与者、授权范围和结束共享操作。

免费服务需要明确每会话时长、并发数、速率和流量上限，并评估中继带宽、滥用防护和运营成本。可先设计协议与威胁模型，再以限量试运行验证成本；不要在成本未验证前承诺永久免费。

### 6. 内网穿透与 FRP 管理器

已加入网络工具中的 STCP 配置管理器，可保存 FRP `service` / `visitor` 的地址、服务名称、目标 / 本机端口、限速和启用标记；共享密钥由用户选择保存到当前 Windows 用户的凭据管理器，导入 / 导出只迁移非敏感参数。窗口会明确显示“只管理配置，不自动启动”，当前没有 frpc 进程、在线服务端连接、监听端口或隧道状态管理。

用户希望内置 FRP 客户端和管理器，通过 `STCP` 访问内网 SSH 等设备。STCP 由内网服务端运行代理，远程访问端运行 visitor 并持有匹配的密钥；两端都主动连接 FRP 服务端，由服务端中转数据，不需要把被访问的 SSH 端口开放为公网端口。远程端可将受授权的 SSH 服务映射到本机端口，再由 EmbedDesk 的 SSH 会话连接。FRP 服务端仍需有公网可达地址，并承担转发流量。

该能力应按“仅访问用户明确选择的服务”设计，不等同于完整 VPN 路由。需明确 visitor 的密钥分发、轮换与撤销方式，并限制可访问的目标服务。若集成 FRP，需要固定并核验上游版本、随包保留 Apache-2.0 许可与来源、及时跟进安全更新，并管理客户端进程生命周期、配置和日志脱敏。可以先做连接配置和状态管理，再接入自有或用户自备服务端；免费公共中继作为单独服务项目评估。

## 需要后续确认的产品选择

- 更新采用仅提示下载，还是确认后自动下载并在重启时替换；签名与发布密钥如何管理。
- 串口协作是否始终通过中继，还是优先尝试点对点并按条件回退；免费配额如何覆盖中继成本。
- FRP 是否仅管理用户自有服务端，还是由 EmbedDesk 提供公共节点；两者的责任、限额和隐私边界不同。
- S3 后续补充匿名访问、ACL / 策略管理、预签名分享或断点续传的优先级。
- 是否需要跨设备配置同步。当前建议先做本机持久化与可导入 / 导出的非敏感配置，不把密码、私钥或串口历史同步到云端。

# 局域网文件分享

网络工具中的独立服务端 / 客户端，不需要中继、网络盘或额外 EXE。双方使用新版 EmbedDesk，通过可信 IPv4 局域网的 TCP HTTP 传输；UDP 39127 仅发现服务，不承载文件正文。文件内容、访问码和连接信息都不加密。

## 复制、导入与目录浏览

服务端选择共享根目录并启动，地址和访问码支持选中复制。「复制连接信息」生成 `EMBEDDESK-FILES:` 前缀加 Base64 编码的 UTF-8 JSON：`Version` 为 1，`Addresses` 为候选地址，`AccessCode` 为本次访问码，不包含共享根目录。客户端「从剪贴板导入」后点击刷新；多网卡时从下拉框选择可达地址，也可以主动发现或手动填写。

Base64 只是编码，获得连接信息的人也获得本次访问码。重启服务会更换访问码，监听端口也可能变化，应重新复制。剪贴板文本最多 16 KiB、解码最多 8 KiB、最多 32 个地址，仅接受局域网 HTTP IPv4 根地址，拒绝 URL 用户信息、路径、查询及片段。无效导入不修改表单或目录，前台操作期间禁止导入和编辑目标；已排队的上传任务单独保存目标地址、目录及访问码，不会随表单变化转发到其他服务器。

客户端双击目录进入共享根目录下的任意子目录；「上级目录」逐级返回，到根目录 `/` 后禁用。服务端同时限制路径，拒绝越界、绝对路径、ADS、保留的续传文件、符号链接和 junction，不防御共享主机恶意程序并发替换目录的竞态。

## 传输面板与后台保留

「上传文件」可以一次选择多个文件，最多同时上传 3 个文件，每文件默认 3 路并行发送分块；等待任务自动接续。有任务时右下角出现悬浮入口，显示未完成数量，点击后展开内部传输面板；每项显示进度、实时速率和预计剩余时间，支持暂停、继续、失败后重试、清除完成及收起。列表最多保留 200 项；同一服务器同一目标不能重复排队。下载目前为单个前台任务，可暂停并再次选择原保存位置续传，不加入并行上传队列。

上传完成后若仍浏览原服务器和目录，会刷新目录内容。后台任务使用排队时的目标信息；继续任务时，只有当前表单仍为原服务器，才更新该任务的访问码。重启服务后可填写新访问码继续；若监听地址改变，需要在新地址重新选择原文件发起续传。

关闭有活动服务或未完成任务的窗口时，可选择「后台保留」「停止并关闭」或取消。后台保留只隐藏窗口，服务地址、访问码和任务继续有效；再次从网络工具打开会恢复原实例。主窗口收起到托盘仍保留这些服务，真正退出 EmbedDesk 才取消任务、等待读写退出并释放监听。后台保留依赖 EmbedDesk 进程存活，不安装 Windows 服务；任务列表不跨程序重启保存，但磁盘上的续传记录保留。

## 快速开始、分块校验与续传

移除传输前后整文件 SHA-256 扫描。文件版本指纹仅读取长度、时间元数据和首尾最多各 64 KiB，耗时不随数十 GiB 文件大小线性增长；它不是完整内容摘要，不能保证检测保持元数据及首尾不变的中间内容修改。传输期间持有只读共享文件句柄，正常 Windows 写入不能同时修改源文件。

上传每块最大 4 MiB，网络接收与 SHA-256 校验并行进行，然后在短临界区定位写入、刷盘并原子替换小型续传记录。只有连续完整前缀推进提交偏移，乱序块不会跨过空洞。重试或重启从服务端确认的连续前缀继续，丢弃最多 4 个尚未连续提交的块并重传。所有块到齐且源版本未变后原子替换目标；没有完成扫描等待，覆盖仍需确认。完成回执支持提交响应丢失后重试。

下载先获取长度、快速指纹和版本，再以最大 4 MiB 的 HTTP Range / If-Match 请求逐块读取。客户端检查 `206`、范围、长度与每块 SHA-256，通过后才写入并保存提交偏移；未提交的尾部截断重传。结束时再次确认远端版本和长度，再原子替换目标。远端版本变化或收到损坏分块会停止，保留原目标文件。

断网、暂停、停止窗口或退出后，未完成数据保留。再次选择同一源文件与目标，或同一下载保存位置，可继续；服务端重启后需重新获取地址 / 访问码。短暂网络故障最多自动重试两次，退避为 500 / 1000 毫秒；认证、覆盖冲突、分块校验失败等不自动重试。SHA-256 在分块传输时检查数据，不提供加密或恶意服务端身份保证。为避免额外读盘，续传不重新扫描已提交的旧块，不能据此宣称检测后续磁盘静默损坏或介质故障。

## 文件大小、磁盘和缓存

不设固定单文件大小上限，长度和偏移使用 64 位整数，不按总大小分配内存。实际最大文件取决于 Windows、文件系统和空间。开始和续传检查剩余空间；FAT32 超过 4 GiB 时提示使用 NTFS / exFAT。UNC 目录以实际写入错误为准。空间变化导致失败时保留提交进度；替换已有文件仍需为完整临时文件预留空间。

续传数据在目标同一目录：上传为 `.embeddesk-upload-<名称摘要>.part/.json.v2`，下载为 `.embeddesk-download-<名称摘要>.part/.json`。这些名称保留，文件工具不展示或允许访问。记录含指纹、长度、提交偏移及少量乱序块信息，不存访问码。下载完成删除记录；上传完成保留每目标一份小型回执。旧版完整哈希缓存不一定匹配新指纹，升级后可能重新传输一次。

未完成部分不会因关闭自动删除；不再需要时，在无活动任务且服务停止后，可删除对应 `.part`、`.json`、`.json.v2` 和残留的 `.new` 记录，删除即丢失进度。旧版 `.json` 上传记录也可清理。不提供任务合并、自动目录同步、UDP 文件加速或跨公网传输。

## 协议与资源

请求带 `X-EmbedDesk-Code`，相对路径通过 `path` 查询指定。`GET /api/list` 浏览目录，`GET /api/file-info` 返回长度 / 快速指纹 / 版本，`GET /api/download-chunk` 提供有界范围和 `X-EmbedDesk-Chunk-Hash`。上传使用 `POST /api/upload-v2-state`、`PUT /api/upload-v2-chunk`、`POST /api/upload-v2-commit`，携带 `X-EmbedDesk-File-Length`、`X-EmbedDesk-File-Id` 和覆盖许可；分块另带 `X-EmbedDesk-Offset`、`X-EmbedDesk-Chunk-Hash`，协议最多 4 路且必须按 4 MiB 边界分块。旧版上传与直接 Range 下载入口仅兼容保留，不供当前客户端选择；新分块能力要求双方使用新版。

最多 16 个并发请求，目录最多 5,000 项。每个传输分块最多 4 MiB 缓存，复制缓冲 64 KiB，请求头最多 16 KiB。连接超时 10 秒，传输状态 / 下载响应头 30 秒，上传分块 60 秒，读写空闲 30 秒。所有等待均支持取消。UDP 最多四轮发现、间隔 350 毫秒，不包含访问码；跨广播域不会自动发现。无代理、HTTP 重定向或公网文件通道。

## 验证边界

`--lan-files-check` 覆盖连接包、剪贴板、子目录双击 / 上级 / 根边界、默认 / 最小尺寸截图、本机 TCP 上传下载、3 文件队列上限、单文件并行、暂停继续、失败重试、切换表单不改变任务目标、隐藏服务可访问和原实例恢复、停止清理、空文件、路径限制、跨实例 / 服务重启续传、乱序块空洞、损坏分块拒绝、实际 TCP 断线及上传响应丢失后的重试。

稀疏文件验证超过 20 GiB 偏移的下载范围、上传分块和快速文件信息，没有完整传输 20 GiB 文件，不能替代跨机局域网、真实断电或磁盘故障实测。

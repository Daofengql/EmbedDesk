# 设备连接与共享服务

连接中心统一管理设备身份、授权和连接路径。串口共享与 TCP / UDP 端口映射复用同一设备会话；局域网文件工具保持独立。操作步骤见[连接中心指南](guide/connection-center.md)，本文描述当前实现与协议边界，服务端部署见[中继说明](../server/README.md)。

## 使用流程

1. 新安装默认使用内置免费中继。自部署节点可在右上角设置的“中继服务器”页面添加名称、HTTP / HTTPS 地址和该中继的准入 Token，或从剪贴板导入管理员提供的连接代码；未启用准入的节点可留空 Token。核对后点击“添加”或“更新”，再选择默认中继并保存。打开设置时会并行请求每个服务器的 `/health`，显示服务状态和延迟；健康检查不验证准入 Token。Go 服务仅监听 HTTP，公网 HTTPS 由 Nginx 等反向代理提供。内置免费节点使用 HTTPS / WSS 地址，客户端正常校验证书及主机名。保存设置不会中断当前连接，连接选项在下次上线时生效。
2. 软件启动后自动上线，优先使用默认中继；默认节点健康检查失败时尝试免费和备用节点，全部暂不可用时仍使用默认地址并由 WebSocket 重连。连接中心大号显示本机设备 ID 和连接密码，底部集中管理映射。节点自动监听，无需选择客户端或服务端角色。
3. 在连接中心的“映射设置”中管理本机资源。未作为连接方连上其他设备时，左侧通过“添加串口”选择要发布的串口，选择框与列表显示扫描得到的设备描述和制造商；右侧通过统一的“添加服务”入口发布目标，在弹窗中选择 TCP 或 UDP，编辑时保留当前协议并允许修改。串口与网络服务使用各自入口，编辑器不提供二者之间的切换。目标可以是回环地址，也可以是该设备所在网络中的主机或开发板，由被连接方解析和访问。串口调试页面不再提供共享服务入口。
4. 连接方输入对方 ID 和密码；密码留空时请求对方人工授权。等待期间可以取消请求或停止上线。授权最长等待 90 秒。
5. 对方发布的 COM 自动出现在串口选择列表。作为连接方并建立设备会话后，“映射设置”分别显示串口映射和端口映射。点击对应列的添加按钮，在弹窗内先选择对端已发布的 COM 或 TCP/UDP 目标，再选择应用内串口、真实虚拟 COM 对或本机回环端口；网络协议随目标固定。规则显示本地入口、对端设备及目标，分别启用、停用和删除。提交前重新核对本次选择的设备会话和服务，目标离线、端口无效或占用会显示错误。网络工具中的映射设置窗口复用相同配置与运行状态。

连接方与被连接方角色互斥，待授权和握手也占用对应角色：存在入站连接或待授权请求时不能主动连接；发起连接或持有出站会话时拒绝入站。相同方向仍允许多设备会话，全部相关请求和会话结束后才可切换方向。客户端与中继均检查，取消和断开会释放角色，不新增手动角色选择。

客户端上线状态以“可用带宽”显示服务端分配的速率，按 1000 进制自动选择 bps、Kbps、Mbps、Gbps 等单位，保留最多三位小数；例如 `4096 Mbps` 显示为 `4.096 Gbps`。仅改变显示，不改变限速值和账号共享规则。右上角节点名称旁显示当前中继 HTTP 延迟，探测结束约 5 秒后再次刷新，沿用本次上线的代理与证书设置；≤100 ms 为绿色、101–200 ms 为黄色、>200 ms 为红色，并始终显示数值。灰色表示探测中、未连接或不可用；失败自动重试，不修改设备连接状态。此值包含 HTTP 连接和 TLS 握手耗时，不代表对端设备或局域网直连的往返延迟；停止上线、切换节点和退出时取消并等待探测结束，设置保存不切换正在探测的节点。

映射方向固定为 `连接方 127.0.0.1:LOCAL_PORT → 被连接方发布的服务 → TARGET_HOST:TARGET_PORT`。连接方只填写本机端口，TCP 和 UDP 均只能监听 `127.0.0.1`，不提供监听范围选择。没有方向选择、反向映射、任意网段访问或 VPN。规则保存协议，重启、掉线后只恢复配置，必须手动启用；启用监听不代表目标已经打开，第一次本机 TCP 连接或 UDP 报文到来时才请求目标通道，失败会显示原因。同一个本机端口号可以分别用于 TCP 和 UDP 映射。

UDP 按本地发送方 IP / 端口分配独立服务通道，被连接方为每条通道创建连接到指定目标的 UDP socket，回复只返回原发送方。空报文和最大 65,507 字节报文保持边界；隧道内按 8 KiB 分帧、单通道顺序重组，每通道最多一个未完成报文。UDP 仍通过认证 TCP 直连或加密 WebSocket 传输，没有 UDP 打洞；中间可靠链路的排队可能增加延迟。每映射最多 32 个发送方，每发送方队列最多 8 条报文，缓冲或发送方数量超限会丢弃并累计显示，操作系统或真实 UDP 网络上的丢包不包含在此计数中。空闲 60 秒的发送方通道自动释放，下次发包重新建立；停用映射和设备断开取消队列并释放监听与目标 socket。

中继列表保存名称、地址和默认节点，旧单地址配置自动迁移，并保留原有有效默认节点。客户端目录提供正式授权的免费节点，新安装默认使用第一个内置节点，已有配置会补入内置节点。测速为单个小 HTTP 健康请求，超时 3 秒、响应上限 4 KiB，并校验协议版本；沿用已保存的代理和 TLS 信任选项，关闭设置取消未完成探测。默认节点可用时不等待其他节点；默认不可用时并行探测备用列表，优先内置免费节点，再按响应延迟选择自定义备用节点。启动选定节点后在该节点上保活 / 重连，不自动跨中继迁移活动会话。

自定义准入 Token 按中继条目及地址分别存入 Windows 凭据管理器，注册只读取最终选中节点的 Token，不会把默认节点的 Token 发送给备用节点。内置节点的公共扫描过滤值由客户端目录提供，仅用于目录中匹配的节点，不继承旧全局密钥。旧全局准入密钥仅兼容已有自定义条目；下次保存设置时迁移为各条目的独立 Token，以后新增的节点不继承旧值。编辑时可清空自定义节点的 Token 并点击“更新”；取消设置不提交导入或编辑的 Token。

连接代码为 `EMBEDDESK-RELAY:` 加 Base64 编码的 UTF-8 JSON，版本 1 包含 `version`、`name`、`url`、`admissionToken`。代码上限 16 KiB，解码数据上限 8 KiB，Token 最多 2048 个不含空白和控制字符的 ASCII 字符。导入同一地址时在编辑区预览替换，保留原条目 ID 和默认选择，不自动创建重复节点。可以在桌面选中条目“复制连接代码”，或由服务端显式运行 `--connection-code PUBLIC_URL NAME` 生成；代码不包含设备身份、设备连接密码、代理口令、TLS 私钥或本地证书路径。

连接代码包含节点公共准入 Token，Base64 不是加密。该 Token 由节点管理员统一维护，仅用于简单过滤扫描请求，不是个人登录凭据、HTTPS 证书、设备归属证明或访问其他设备的授权；设备访问仍需密码或人工授权。控制台更新 Token 立即用于后续注册，不主动断开现有连接；客户端再次注册前应导入当前连接代码。控制台开启后，节点名称、公开地址、Token 和默认带宽首次从启动配置初始化，随后以数据库设置为准。CLI 导出只读取启动配置，当前节点代码优先从控制台“中继接入”页复制。

设备首次接入为匿名设备。注册用户可在网页控制台输入自己客户端的设备 ID，绑定尚未归属账号的设备；已属于其他账号的设备不能直接领取，管理员可调整归属。知道未绑定 ID 即可领取，这个流程不证明真实设备持有。访客是只读控制台账号，只能查看管理员分配的资源。绑定、转移归属或清空归属会断开该设备，以便重连后应用账号共享配额或匿名设备默认值。

一个已授权的设备会话允许访问被连接方当前发布的全部服务；服务目录中的每一项限定一个 COM、TCP 或 UDP 目标。目录通过已授权双方的加密通道提供目标地址和端口，供添加弹窗和映射规则显示；实际打开仍按被连接方本机服务标识解析，不接受连接方任意指定目标。旧客户端未提供网络目标地址时明确显示未知，不能从服务名称猜测端口。本期没有额外的逐服务授权弹窗。修改共享配置前需要关闭活动服务通道。串口设备描述仅来自当前本机扫描，不写入设置或发送到中继。使用 UDP 服务时两端桌面客户端都需更新；中继继续转发加密数据，无需为 UDP 新增监听端口。

## 身份、认证与数据路径

客户端在 Windows 凭据管理器保存随机 32 字节设备凭据，以设置位置和中继地址区分身份。服务端由凭据摘要生成稳定的 12 位十六进制 ID；不读取硬件序列号。更换机器、清除凭据或更换中继会产生新的身份。MySQL 或 SQLite 保存 ID、凭据 SHA-256、账号归属和登记时间，设备连接密码不上传或写入数据库。

动态密码在应用启动上线或手动重新上线时生成，自动重连沿用本轮密码；静态密码至少 8 个字符，也可以禁用密码连接、仅接受人工授权。设备凭据、中继准入 Token、连接密码和代理密码不进入普通 JSON 设置文件。

HTTP 注册和设备查询与设备凭据认证的 WebSocket 共用根地址；HTTP 对应 `ws`，HTTPS 对应 `wss`。Go 中继本体不管理证书、私钥或 TLS 监听。公网中继的全局控制和数据始终走同一条 WebSocket，无独立裸 TCP 中继端口；认证局域网 TCP 直连仍保留。连接请求、握手和关闭在 WebSocket 中路由，并由服务端绑定发送者 ID、校验成员、角色与握手阶段。

客户端每 20 秒发送应用心跳；服务端每 25 秒 Ping，读 / Pong 超时 75 秒、写超时 15 秒。客户端 75 秒无业务或心跳响应会关闭连接；心跳发送失败也会触发断线清理。受限数据使用有界队列，带宽等待不阻塞服务端控制、Ping/Pong 或心跳。重连以设置的首次等待为基准指数退避，加入随机抖动，上限 300 秒；连接稳定一分钟后才重置退避，避免反复升级 / 断线造成重连风暴。重连保留本轮设备凭据与密码，仅恢复节点上线，不恢复已授权会话、实际 COM 或映射。

密码认证采用 PBKDF2-SHA-256（100,000 次，salt 绑定会话及双方 ID）和握手角色证明；P-256 ECDH 与 HKDF-SHA-256 派生双向独立密钥。业务帧使用 AES-GCM、连续序号和 nonce 校验，验证失败终止该设备会话。此协议不是经过第三方审计的 PAKE，密码应有足够随机性。

仅 ID 人工授权时，批准方生成本次随机配对密钥，由可信中继引介。服务端不落盘该密钥，但它经过服务端内存；该模式依赖中继诚实和传输链路可信，不能据此宣称能抵抗恶意中继主动冒充。公网部署使用 HTTPS 反向代理。HTTP / WS 模式会明文传输设备凭据、人工授权配对密钥和握手消息，仅用于可信内网；业务帧仍使用 AES-GCM，但它不能替代认证链路的 TLS。密码握手的证明、设备 ID、在线关系和候选地址也会经过中继。

授权后被连接方发布私有 IPv4 / link-local IPv4 候选地址和自动监听端口。连接方在总计 3 秒内尝试 TCP 直连，用双方会话密钥和随机挑战认证；失败自动回退到公网中继。当前没有 IPv6 直连、互联网 UDP 打洞或脱离中继的 ID 查询与授权。直连建立后发生断线会结束本次会话，需要重新连接；没有运行中无缝迁移。中继掉线也会清理直连会话与活动映射。

代理设置支持直连、系统代理和自定义 HTTP / HTTPS / SOCKS5 URL；HTTP 注册与 WebSocket 共用选项，局域网 TCP 直连不走代理。“连接安全”中的额外 PEM 根证书用于 HTTPS 链路信任，与准入 Token 独立；仍验证主机名和证书链，不提供忽略 TLS 错误开关。自定义根链当前不做联网吊销检查。

## 串口资源规则

`SharedSerialPortService` 为应用内统一资源管理器，覆盖串口调试、共享和使用 `ISerialPortService` 的烧录工具。

- 启用共享仅做软件预留，不预打开 COM，不改变波特率、DTR 或 RTS。本地已占用时不能启用共享，需先结束本地连接。
- 预留期间本地调试和烧录不能打开该 COM；其他程序仍可打开，不具备系统级锁定效果。
- 连接方真正打开远端串口时，提交波特率、数据位、校验、停止位、流控、DTR 和 RTS；被连接方成功打开实际设备后才返回成功。同一 COM 同时只允许一个远端使用。
- 外部占用、设备缺失、访问拒绝、参数错误及收发失败按实际原因返回连接方。单通道失败不应中断全局中继；本次设备占用被释放，共享预留保留。
- 远端关闭或会话结束释放实际 COM；取消共享后恢复本地使用。连接方可在添加串口映射弹窗中选择对端串口，再选择应用内使用（默认、无需驱动），或复用已安装的 com0com 串口对映射为系统虚拟 COM（实验性）。系统映射根据外部软件的打开状态按需打开远端硬件，配置变化复用加密会话下发并确认；不会自动安装或删除驱动。当前支持范围及验证边界见 [可选系统虚拟串口](VirtualSerialPorts.md)。

## 流控与资源限制

匿名设备每台使用节点默认带宽；绑定设备按账号共享带宽，**同一账号下所有设备、全部会话的上传和下载合计共用一个总预算**。同账号设备互传按每端 RX/TX 计入该预算。范围为 8 Kbit/s–100 Gbit/s，默认示例 1 Mbps；注册响应返回匿名设备额度或所属账号共享总额度，不能将后者理解为账号下每台设备各得一份。

管理员可以修改单用户总配额，关联设备会断开并在重连后应用新值。节点默认带宽作为后续新注册账号的总配额初值，不覆盖已有用户；已在线匿名设备下次重连后使用新默认值。首次启用控制台由 `bandwidthBitsPerSecond` 初始化节点默认带宽，以后控制台数据库设置为准。计量 JSON 中加密数据 body 的字节数，包含加密和 Base64 封装，不等于业务有效负载速率。初始令牌桶允许 64 KiB 突发；局域网直连业务不受中继额度限制。

| 范围 | 当前限制 |
| --- | --- |
| 每客户端设备会话 / 待发请求 | 16 / 8 |
| 每设备会话活动服务通道 | 32 |
| 每客户端共享服务 / 本机保存映射规则 | 128 / 128，服务目录总编码不超过 32 KiB |
| 服务数据块 / RPC / 全局中继报文 | 8 KiB / 32 KiB / 96 KiB |
| 每通道在途数据额度 / 发送队列 | 8 / 8 |
| UDP 报文 / 每映射发送方 / 每发送方待发队列 | 65,507 字节 / 32 / 8 条报文 |
| 每会话控制发送 / RPC 接收队列 | 128 / 512 |
| 中继在线设备 / 总设备会话 | 1,024 / 4,096 |
| 中继每客户端控制出队列 / 数据出队列 / 数据入队列 | 各 64 项 |
| 控制报文与全局 HTTP 准入请求 | 20 次/s，允许 40 次突发 |

控制报文优先，数据按通道轮询；TCP 和串口都等待对端消费额度。串口驱动后台回调以不超过 8 KiB 的数据块施加可取消背压，八条在途额度暂时耗尽时等待回执，不再关闭健康串口。额度回执独立于业务写入处理，避免双向串口收发互相等待；关闭通道或设备断线先取消等待再释放驱动。系统虚拟 COM 使用独立的有界收发泵，慢接收端不会因发送正在等待额度而阻塞反向写入。软件背压不能替代物理设备的 RTS/CTS 或 XON/XOFF；持续输入超过链路与驱动容量时仍可能发生硬件侧溢出，按用户串口参数选择流控，不自动改变控制线。

UDP 待发队列超限按报文丢弃并显示计数，已进入隧道的报文沿用通道消费额度。超时、掉线和关闭取消读写并清理实际流；会话队列满时关闭连接。总吞吐有界，但不保证每个交互通道的严格延迟。

## 独立局域网文件工具

在网络工具中打开「局域网文件」。服务端启动后可选中复制地址 / 访问码，也可「复制连接信息」，对方「从剪贴板导入」。Base64 仅编码，连接包包含本次访问码；重启后重新获取。支持共享根目录内子目录浏览、上传下载、暂停续传和覆盖确认；上传通过内部任务面板同时处理 3 个文件，每文件默认 3 路分块。关闭窗口可后台保留，重开恢复同一实例，真正退出才清理；详细流程及缓存说明见 [局域网文件](LanFiles.md)。

TCP 是文件可靠传输主通道，UDP 辅助主动发现，不承载文件正文。发现使用 UDP 39127 广播、各网卡定向广播与回环发现，最多发送四轮探测、间隔 350 毫秒，响应声明 `tcp-http` 能力并去重；发现失败可手动输入 TCP HTTP 地址。文件监听使用自动分配的 TCP 端口。防火墙需要允许相关入站流量，跨广播域不会自动发现。仅接受私有 / link-local / 回环 IPv4 地址，不通过中继、代理或 HTTP 重定向。发现报文不包含访问码。

文件协议为独立 .NET 实现的有限 HTTP GET / POST / PUT，传输与访问码均**不加密**，适用于可信局域网。上传下载使用最大 4 MiB 分块、逐块 SHA-256 与持久化提交偏移，下载另有 HTTP Range / If-Match；移除整文件扫描，以元数据和首尾最多 128 KiB 采样确认版本，所有块提交后才原子替换目标。采样不是完整内容摘要，续传不复扫已提交旧块，不承诺检测缓存后续静默损坏。中断保留进度和原文件，短暂断线最多自动重试两次。路径限制在共享根目录，拒绝越界、绝对路径、ADS、符号链接和 junction；不防御共享主机恶意程序并发修改目录的竞态。

每目录最多 5,000 项、同时最多 16 个请求；不设固定单文件大小上限，使用 64 位长度与偏移，检查剩余空间及 FAT32 限制。分块缓存最多每请求 4 MiB，复制缓冲 64 KiB，请求头上限 16 KiB。TCP NoDelay，保持连接 / 分块 / 空闲超时及取消。当前无 UDP 正文加速、目录同步、跨公网文件或服务配置持久化。

## 设置、托盘与兼容

右上角设置管理中继服务器列表、默认节点、重连、代理、安全和关闭偏好。启动后自动上线，不提供单独的自动连接开关。主窗口关闭默认询问收起到托盘、退出或取消，并可记忆选择；托盘保留连接、共享预留、活动串口和转发，双击恢复原窗口，待授权请求有通知。托盘退出执行真实清理并处理未保存文档与活动连接确认。

设置 schema 3 兼容迁移 schema 1 / 2 的主导航索引及普通网络预设，保存非敏感连接选项、共享服务、最近设备 ID 和映射规则。旧 EDBG 手动桥接和 FRP service / visitor 实现及配置保留用于兼容和回归，不再作为正常产品入口，也不会自动启动旧连接。配置包 schema 2 兼容导入旧格式，当前产品入口仅导入 / 导出命名远程连接与旧桥接 / STCP 资料，不导入 / 导出调试助手或网络旧预设，也不包含凭据、活动连接或连接中心的新共享服务与映射规则；历史预设仅保留文件读取兼容。

## 验证与边界

本机检查使用真正 HTTP-only Go 中继和两个 .NET 节点，覆盖密码 / 人工授权、取消、TCP 完整性、UDP 空报文 / 分帧 / 最大报文 / 双发送方回复隔离 / 突发丢弃 / TCP 同端口共存、串口模拟设备、直连和失败回退、进程断线 / 重启后自动重连与资源释放。TLS 信任 / 主机名和 HTTP CONNECT 代理由独立 .NET TLS 终止测试夹具验证，不代表实测 Nginx 部署。Go 测试覆盖配置校验、实际限额、双向限速和带宽等待期间的心跳。独立文件检查覆盖发现重试 / 去重 / 取消、空文件、分片请求头和合并正文、上传下载、覆盖、越界 / junction、取消与清理。桌面检查包含默认 / 最小尺寸截图、设备描述、固定发布类型、串口侧栏不重叠、设置、共享窗口和托盘保留连接。

入口为 `--device-connections-check`、`--device-security-check`、`--lan-files-check`、`--connection-center-window-check` 和 `--app-settings-check`；设备检查前先构建 `artifacts/relay-test.exe`。不需要公共节点。尚未进行真实公网部署、跨机局域网、防火墙穿越、实物 COM 或生产代理 / SOCKS5 互通验收；模拟设备结果不能替代硬件验证。

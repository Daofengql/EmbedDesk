# 设备连接、共享服务与局域网文件

连接中心统一管理设备身份、授权和连接路径。串口共享与 TCP / UDP 端口映射复用同一设备会话；局域网文件工具保持独立。本文描述首期实际实现，服务端部署见 [中继说明](../server/relay/README.md)。

## 使用流程

1. 在右上角设置的“中继服务器”页面添加一个或多个 HTTP / HTTPS 地址，选择默认中继并按部署要求填写准入密钥；默认没有预置公共节点。打开设置时会并行请求每个服务器的 `/health`，显示在线状态和延迟。Go 服务仅监听 HTTP，公网 HTTPS 由 Nginx 等反向代理提供。保存设置不会中断当前连接，连接选项在下次上线时生效。
2. 软件启动后自动上线，优先使用默认中继；默认节点健康检查失败时尝试免费和备用节点，全部暂不可用时仍使用默认地址并由 WebSocket 重连。连接中心大号显示本机设备 ID 和连接密码，底部集中管理映射。节点自动监听，无需选择客户端或服务端角色。
3. 在连接中心的“映射设置”中管理本机资源。未作为连接方连上其他设备时，左侧通过“添加串口”选择要发布的串口，选择框与列表显示扫描得到的设备描述和制造商；右侧通过统一的“添加服务”入口发布目标，在弹窗中选择 TCP 或 UDP，编辑时保留当前协议并允许修改。串口与网络服务使用各自入口，编辑器不提供二者之间的切换。目标可以是回环地址，也可以是该设备所在网络中的主机或开发板，由被连接方解析和访问。串口调试页面不再提供共享服务入口。
4. 连接方输入对方 ID 和密码；密码留空时请求对方人工授权。等待期间可以取消请求、处理其他授权或停止上线。授权最长等待 90 秒。
5. 对方发布的 COM 自动出现在串口选择列表。作为连接方并建立设备会话后，“映射设置”切换为远程模式：左侧列出对端发布的服务，右侧列出本机映射规则；选择服务并保存后才启用本机监听，不会随设备连接自动开启。网络工具中的映射设置窗口复用相同配置与运行状态。

映射方向固定为 `连接方 127.0.0.1:LOCAL_PORT → 被连接方发布的服务 → TARGET_HOST:TARGET_PORT`。没有方向选择、反向映射、任意网段访问或 VPN。规则保存协议，重启、掉线后只恢复配置，必须手动启用；启用监听不代表目标已经打开，第一次本机 TCP 连接或 UDP 报文到来时才请求目标通道，失败会显示原因。同一个本机端口号可以分别用于 TCP 和 UDP 映射。

UDP 按本地发送方 IP / 端口分配独立服务通道，被连接方为每条通道创建连接到指定目标的 UDP socket，回复只返回原发送方。空报文和最大 65,507 字节报文保持边界；隧道内按 8 KiB 分帧、单通道顺序重组，每通道最多一个未完成报文。UDP 仍通过认证 TCP 直连或加密 WebSocket 传输，没有 UDP 打洞；中间可靠链路的排队可能增加延迟。每映射最多 32 个发送方，每发送方队列最多 8 条报文，缓冲或发送方数量超限会丢弃并累计显示，操作系统或真实 UDP 网络上的丢包不包含在此计数中。空闲 60 秒的发送方通道自动释放，下次发包重新建立；停用映射和设备断开取消队列并释放监听与目标 socket。

中继列表保存名称、地址和默认节点，旧单地址配置自动迁移。测速为单个小 HTTP 健康请求，超时 3 秒、响应上限 4 KiB，并校验协议版本；沿用已保存的代理和 TLS 信任选项，关闭设置取消未完成探测。默认节点可用时不等待其他节点；默认不可用时并行探测备用列表，优先内置免费节点，再按响应延迟选择自定义备用节点。免费节点尚未正式部署，目录目前为空。启动选定节点后在该节点上保活 / 重连，不自动跨中继迁移活动会话。

一个已授权的设备会话允许访问被连接方当前发布的全部服务；服务目录中的每一项限定一个 COM、TCP 或 UDP 目标。本期没有额外的逐服务授权弹窗。修改共享配置前需要关闭活动服务通道。串口设备描述仅来自当前本机扫描，不写入设置或发送到中继。使用 UDP 服务时两端桌面客户端都需更新；中继继续转发加密数据，无需为 UDP 新增监听端口。

## 身份、认证与数据路径

客户端在 Windows 凭据管理器保存随机 32 字节设备凭据，以设置位置和中继地址区分身份。服务端由凭据摘要生成稳定的 12 位十六进制 ID；不读取硬件序列号。更换机器、清除凭据或更换中继会产生新的身份。SQLite 保存 ID、凭据 SHA-256 和登记时间，连接密码不上传或写入数据库。

动态密码在应用启动上线或手动重新上线时生成，自动重连沿用本轮密码；静态密码至少 8 个字符，也可以禁用密码连接、仅接受人工授权。设备准入凭据、连接密码和代理密码不进入普通 JSON 设置文件。

HTTP 注册和设备查询与设备凭据认证的 WebSocket 共用根地址；HTTP 对应 `ws`，HTTPS 对应 `wss`。Go 中继本体不管理证书、私钥或 TLS 监听。公网中继的全局控制和数据始终走同一条 WebSocket，无独立裸 TCP 中继端口；认证局域网 TCP 直连仍保留。连接请求、握手和关闭在 WebSocket 中路由，并由服务端绑定发送者 ID、校验成员、角色与握手阶段。

客户端每 20 秒发送应用心跳；服务端每 25 秒 Ping，读 / Pong 超时 75 秒、写超时 15 秒。客户端 75 秒无业务或心跳响应会关闭连接；心跳发送失败也会触发断线清理。受限数据使用有界队列，带宽等待不阻塞服务端控制、Ping/Pong 或心跳。重连以设置的首次等待为基准指数退避，加入随机抖动，上限 300 秒；连接稳定一分钟后才重置退避，避免反复升级 / 断线造成重连风暴。重连保留本轮设备凭据与密码，仅恢复节点上线，不恢复已授权会话、实际 COM 或映射。

密码认证采用 PBKDF2-SHA-256（100,000 次，salt 绑定会话及双方 ID）和握手角色证明；P-256 ECDH 与 HKDF-SHA-256 派生双向独立密钥。业务帧使用 AES-GCM、连续序号和 nonce 校验，验证失败终止该设备会话。此协议不是经过第三方审计的 PAKE，密码应有足够随机性。

仅 ID 人工授权时，批准方生成本次随机配对密钥，由可信中继引介。服务端不落盘该密钥，但它经过服务端内存；该模式依赖中继诚实和传输链路可信，不能据此宣称能抵抗恶意中继主动冒充。公网部署使用 HTTPS 反向代理。HTTP / WS 模式会明文传输设备凭据、人工授权配对密钥和握手消息，仅用于可信内网；业务帧仍使用 AES-GCM，但它不能替代认证链路的 TLS。密码握手的证明、设备 ID、在线关系和候选地址也会经过中继。

授权后被连接方发布私有 IPv4 / link-local IPv4 候选地址和自动监听端口。连接方在总计 3 秒内尝试 TCP 直连，用双方会话密钥和随机挑战认证；失败自动回退到公网中继。当前没有 IPv6 直连、互联网 UDP 打洞或脱离中继的 ID 查询与授权。直连建立后发生断线会结束本次会话，需要重新连接；没有运行中无缝迁移。中继掉线也会清理直连会话与活动映射。

代理设置支持直连、系统代理和自定义 HTTP / HTTPS / SOCKS5 URL；HTTP 注册与 WebSocket 共用选项，局域网 TCP 直连不走代理。额外 PEM 根证书扩展信任范围，仍验证主机名和证书链；不提供忽略 TLS 错误开关。自定义根链当前不做联网吊销检查。

## 串口资源规则

`SharedSerialPortService` 为应用内统一资源管理器，覆盖串口调试、共享和使用 `ISerialPortService` 的烧录工具。

- 启用共享仅做软件预留，不预打开 COM，不改变波特率、DTR 或 RTS。本地已占用时不能启用共享，需先结束本地连接。
- 预留期间本地调试和烧录不能打开该 COM；其他程序仍可打开，不具备系统级锁定效果。
- 连接方真正打开远端串口时，提交波特率、数据位、校验、停止位、流控、DTR 和 RTS；被连接方成功打开实际设备后才返回成功。同一 COM 同时只允许一个远端使用。
- 外部占用、设备缺失、访问拒绝、参数错误及收发失败按实际原因返回连接方。单通道失败不应中断全局中继；本次设备占用被释放，共享预留保留。
- 远端关闭或会话结束释放实际 COM；取消共享后恢复本地使用。连接方可在“使用串口…”中选择应用内使用（默认、无需驱动），或复用已安装的 com0com 串口对映射为系统虚拟 COM（实验性）。系统映射根据外部软件的打开状态按需打开远端硬件，配置变化复用加密会话下发并确认；不会自动安装或删除驱动。当前支持范围及验证边界见 [可选系统虚拟串口](VirtualSerialPorts.md)。

## 流控与资源限制

每个客户端统一中继额度由 JSON 配置的 `bandwidthBitsPerSecond` 指定，**双向合计、所有会话共用**；范围为 8 Kbit/s–100 Gbit/s，默认示例 1 Mbps。注册响应返回实际额度，客户端状态随之显示，配置在服务端重启后生效。计量 JSON 中加密数据 body 的字节数，包含加密和 base64 封装，不等于业务有效负载速率。初始令牌桶允许 64 KiB 突发。局域网直连业务不受该中继额度限制。

| 范围 | 当前限制 |
| --- | --- |
| 每客户端设备会话 / 待发请求 | 16 / 8 |
| 每设备会话活动服务通道 | 32 |
| 每客户端共享服务 / 本机保存映射规则 | 128 / 128，服务目录总编码不超过 32 KiB |
| 服务数据块 / RPC / 全局中继报文 | 8 KiB / 32 KiB / 96 KiB |
| 每通道在途数据额度 / 发送队列 | 8 / 8 |
| UDP 报文 / 每映射发送方 / 每发送方待发队列 | 65,507 字节 / 32 / 8 条报文 |
| 每会话控制发送 / RPC 接收队列 | 128 / 512 |
| 中继在线设备 / 总设备会话 | 1,024 / 4,096 |
| 中继每客户端控制出队列 / 数据出队列 / 数据入队列 | 各 64 项 |
| 控制报文与全局 HTTP 准入请求 | 20 次/s，允许 40 次突发 |

控制报文优先，数据按通道轮询；TCP 等待对端消费额度，串口回调无法无限等待，缓冲耗尽时明确报错并关闭该串口。UDP 待发队列超限按报文丢弃并显示计数，已进入隧道的报文沿用通道消费额度。超时、掉线和关闭取消读写并清理实际流；会话队列满时关闭连接。总吞吐有界，但不保证每个交互通道的严格延迟。

## 独立局域网文件工具

在网络工具中打开「局域网文件」。服务端启动后可选中复制地址 / 访问码，也可「复制连接信息」，对方「从剪贴板导入」。Base64 仅编码，连接包包含本次访问码；重启后重新获取。支持共享根目录内子目录浏览、上传下载、暂停续传和覆盖确认；上传通过内部任务面板同时处理 3 个文件，每文件默认 3 路分块。关闭窗口可后台保留，重开恢复同一实例，真正退出才清理；详细流程及缓存说明见 [局域网文件](LanFiles.md)。

TCP 是文件可靠传输主通道，UDP 辅助主动发现，不承载文件正文。发现使用 UDP 39127 广播、各网卡定向广播与回环发现，最多发送四轮探测、间隔 350 毫秒，响应声明 `tcp-http` 能力并去重；发现失败可手动输入 TCP HTTP 地址。文件监听使用自动分配的 TCP 端口。防火墙需要允许相关入站流量，跨广播域不会自动发现。仅接受私有 / link-local / 回环 IPv4 地址，不通过中继、代理或 HTTP 重定向。发现报文不包含访问码。

文件协议为独立 .NET 实现的有限 HTTP GET / POST / PUT，传输与访问码均**不加密**，适用于可信局域网。上传下载使用最大 4 MiB 分块、逐块 SHA-256 与持久化提交偏移，下载另有 HTTP Range / If-Match；移除整文件扫描，以元数据和首尾最多 128 KiB 采样确认版本，所有块提交后才原子替换目标。采样不是完整内容摘要，续传不复扫已提交旧块，不承诺检测缓存后续静默损坏。中断保留进度和原文件，短暂断线最多自动重试两次。路径限制在共享根目录，拒绝越界、绝对路径、ADS、符号链接和 junction；不防御共享主机恶意程序并发修改目录的竞态。

每目录最多 5,000 项、同时最多 16 个请求；不设固定单文件大小上限，使用 64 位长度与偏移，检查剩余空间及 FAT32 限制。分块缓存最多每请求 4 MiB，复制缓冲 64 KiB，请求头上限 16 KiB。TCP NoDelay，保持连接 / 分块 / 空闲超时及取消。当前无 UDP 正文加速、目录同步、跨公网文件或服务配置持久化。

## 设置、托盘与兼容

右上角设置管理中继服务器列表、默认节点、重连、代理、安全和关闭偏好。启动后自动上线，不提供单独的自动连接开关。主窗口关闭默认询问收起到托盘、退出或取消，并可记忆选择；托盘保留连接、共享预留、活动串口和转发，双击恢复原窗口，待授权请求有通知。托盘退出执行真实清理并处理未保存文档与活动连接确认。

设置 schema 2 迁移旧版主导航索引，保存非敏感连接选项、共享服务、最近设备 ID 和映射规则。旧 EDBG 手动桥接和 FRP service / visitor 实现及配置保留用于兼容和回归，不再作为正常产品入口，也不会自动启动旧连接。原非敏感配置导入 / 导出仍处理旧格式，本期尚不包含新的连接中心共享服务和映射规则。

## 验证与边界

本机检查使用真正 HTTP-only Go 中继和两个 .NET 节点，覆盖密码 / 人工授权、取消、TCP 完整性、UDP 空报文 / 分帧 / 最大报文 / 双发送方回复隔离 / 突发丢弃 / TCP 同端口共存、串口模拟设备、直连和失败回退、进程断线 / 重启后自动重连与资源释放。TLS 信任 / 主机名和 HTTP CONNECT 代理由独立 .NET TLS 终止测试夹具验证，不代表实测 Nginx 部署。Go 测试覆盖配置校验、实际限额、双向限速和带宽等待期间的心跳。独立文件检查覆盖发现重试 / 去重 / 取消、空文件、分片请求头和合并正文、上传下载、覆盖、越界 / junction、取消与清理。桌面检查包含默认 / 最小尺寸截图、设备描述、固定发布类型、串口侧栏不重叠、设置、共享窗口和托盘保留连接。

入口为 `--device-connections-check`、`--device-security-check`、`--lan-files-check`、`--connection-center-window-check` 和 `--app-settings-check`；设备检查前先构建 `artifacts/relay-test.exe`。不需要公共节点。尚未进行真实公网部署、跨机局域网、防火墙穿越、实物 COM 或生产代理 / SOCKS5 互通验收；模拟设备结果不能替代硬件验证。
